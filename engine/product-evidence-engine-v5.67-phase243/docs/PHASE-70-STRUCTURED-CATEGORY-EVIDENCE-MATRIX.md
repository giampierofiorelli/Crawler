# Phase 70 — A variable-field, category-aware evidence matrix

**Status:** isolated research code + additive, unexecuted PostgreSQL migration. **No live spider, AI extraction, commercial clearance, factual review, licensed review publisher, working PostgreSQL instance, consumer ranking, or accuracy claim.**

## Why

The preferred product is NOT a searchable full-text copy of professional articles. It is a versioned knowledge matrix of narrowly typed product observations that can be reused in evidence-aware, user-context-specific evaluation. This reduces the need to store copyrighted expression and makes missing/contested evidence visible. It **does not** by itself legalise collecting or copying a work, systematically extracting a protected database, or training/running analysis using a source without the necessary rights.

## Design

* `evidence_category_schema` and `evidence_category_field`: category-specific, reviewed and versioned definitions (number with unit, boolean, restricted qualitative enum), required use-case context and source-origin policy. No unconstrained schema auto-expansion by AI.
* `structured_evidence_observation`: one variant × attribute × source observation × exact context × method. Preserves numeric units, qualitative labels (not synthetic scores), source URL, original-test identity, digests, and revision fingerprint. No imported article body/excerpts/embeddings in the data model. Observations in research quarantine by default; never exposed through launch scoring.
* `derived_evidence_hypothesis` + `derived_hypothesis_input`: hypotheses generated by AI are **separate** from source observations and linked to all supporting evidence. No calculated weight, factual status, or publication right is implied.
* `src/category_evidence_matrix.ts`: joins Phase 68/69 quarantine digests to candidate structured values. Enforces controlled types/units, variant and origin, source rights documentation, protocol/context and digest anchoring. Returns reject reasons and zero approved-for-ranking values.
* `matrixCoverageByField()` shows evidence gaps without ranking missing data as poor performance.

## Example (invented, demonstration only)

Headphone fields can include `speech_noise_reduction` as qualitative `high|medium|low|mixed` under `environment=office`, `noise_type=speech`; `battery_runtime` as a measured number in `hours` under specified ANC and playback level; and manufacturer `has_bluetooth` as a documented boolean. Other categories declare their own registry. One source's 'mixed' must never be converted automatically into an invented numeric 7/10. Measurements taken under different protocols or conditions are kept separate, not silently averaged.

## Acquisition decision (web-first, API optional)

Discovery via search engines, publisher feeds, sitemaps and verified permitted web pages. Per-site robots and terms gate, and per-operation documented copyright/database-right permission or reviewed applicable exception precedes automated retrieval. **No paywalls, login bypass, captcha evasion, IP rotation to defeat blocks, or persistent page archives.** Use API only if voluntarily authorized and practically helpful; neither an API nor a robots allowance alone grants reuse rights.

Pipeline: request -> existing matrix gap/staleness query -> candidate discovery -> per-operation policy/terms/robots gate -> limited transient fetch -> local/on-prem analysis only if authorized -> exact field mapping and digest anchoring -> discard raw text -> research quarantine -> human fact/method/rights review -> separate promotion gate for any commercial use. Future revocation should invalidate/promote-block dependent observations; not yet implemented.

**Legal distinction:** The absence of stored original prose reduces reproduction risk, but transient copying may still be relevant, and repeated extraction may infringe database rights. A publisher's usage terms and reservations must also be checked. The system must not treat content that happens to be publicly readable as blanket permission to mine it commercially.

## Evidence standards / blockers

1. This module receives candidate digests from an earlier system that does not authenticate the AI interpretation. It is *syntactic* anchoring, not verified truth, and a caller could forge evidence-processing metadata. No AI interpretation accuracy has been established.
2. Rights policy objects are human-entered attestations, not an automated legal finding; commercial clearance requires assessment per source and operation. Current fail-closed rules require operation permission even for the research matrix.
3. The SQL structure is additive and not applied to a live PostgreSQL server; DB constraints cover only a subset of the application-level validation. Production should add transactionally verified publisher-grant relationship, access roles, source validity, revocation, and audited human approvals.
4. The new module and SQL are **not imported from** `src/launch/index.ts`; outputs never feed ranking. `dist/` remains research-only.
5. No claim of measured scientific confidence, real-review coverage, licensed commercial access, or end-user utility validation.
