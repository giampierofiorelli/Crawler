## Binding product decisions to preserve

1. **Purpose:** personal functional suitability to the person's use, environment and priorities, informed by original, professional, methodologically documented product tests and product-specific technical facts. A specification sheet or publisher stars are not an independent performance test; do not manufacture universal scalar scores.
2. **Evidence reliability:** preserve exact SKU/model/variant, documented methodology, unit, conditions, source rights/provenance, missing-evidence reasons, multi-report versus independent test lineage and uncertainty. Never count a republished test twice.
3. **Needs first:** progressive needs discovery precedes selection/ranking; source discovery is selective based on decision-relevant evidence gaps. Market sufficiency is not the same as number of pages or candidate products found.
4. **Manufacturer declarations:** useful for provisional product identity/eligibility and contextual constraints, separately labelled `manufacturer_declared` and quarantined from independent observed performance. Unknown is not a penalty.
5. **Reviews/experience:** selectively consult only with actual source rights and a decision-relevant gap; never transform unlicensed opinions or review frequencies into measured population performance. No Amazon reviews/ratings as ranking data.
6. **Retailer independence:** purchase links only **after** recommendation, never affiliate economics in the score or source acquisition; no mandatory commercial search/scraping API or Amazon product/price/review feeds. Price is not part of this experimental acquisition lane.
7. **Lifecycle:** differentiate confirmed authoritative manufacturing discontinuation from retailer stock, sold-out, out-of-stock, manufacturer listing visibility and marketing snippets; preserve historical records and bar genuinely retired SKUs only under Phase81 authoritative process.
8. **In-house acquisition:** retain Phase68 source planning, Phase69 safe authorized read (`readApprovedSource`), Phase72 semantic intake/quarantine, Phase75 discovery, Phase79 search sufficiency, Phase80 portfolio population and Phase82 market watch. Use existing low-level commodity HTTP parser tooling and optional Playwright when justified; no adoption of entire Crawl4AI, ScrapeGraphAI, Apify, Firecrawl or agent/browser framework without objective net gain and no new mandatory paid API.
9. **Learning reusable methods:** Phase85 stores source-/category-bounded deterministic numerical JSON-LD extraction recipes, two or more distinct independently labelled samples, separate human review, integrity checks, failure retirement. Phase86 proposes mappings using only bounded property names/units with local Ollama-style model; no raw HTML or numeric fact input to the model, no model self-approval, no model inference on successful reusable recipe visits.
10. **Phase87 HTML extension:** preserve the same rights/approval boundaries. HTML extraction is limited to explicit numeric manufacturer specifications; unsupported layouts fail closed; static HTML is parsed without remote retrieval; SQLite store is an experimental single-host companion, *not* a replacement for Phase85 authoritative multiworker catalog.
11. **Phase88 adapter contract:** source authorization must occur before any extracted value; no redirect or content-type surprise; only reviewed field keys may pass and all facts are quarantined; never invoke local model on a stored recipe. The Phase69 and Phase72 callbacks are **explicit wiring requirements** in the inaccessible mainline.
12. **Testing ethics:** synthetic fixture counts establish only software functionality; do not report source precision/recall, speed superiority, actual live permission, real installed Ollama performance, real reviewer authentication or live ranking quality without external tests.
